## Semantic boundaries

All prose clauses remain evidence-only schema rules without fabricated Boolean effects. Their unsupported meaning is preserved in raw records. Complete source texts remain untranslated coverage because exact quoting and partial transition modeling do not formalize their full semantics. Conditional clauses are not silently treated as unconditional planner prohibitions. Active skills are only those in the corresponding family; optional related skills are not universal prerequisites.

Data lineage remains distinct: measured counts, normalized X, and raw snapshots are different entities. SysVI uses its own normalized-input branch; the SCVI count requirement is not inherited. Workflow tokens are explicit abstraction states, not claims that the checker can inspect actual matrices.

Human verification and approvals are externally supplied human actions. Metadata checks cannot add those facts. No actual submission is modeled. Incomplete draft scaffolds retain unresolved state, banner and submission_ready=false.

Schematics are optional unless the scenario explicitly requires them. Protected-prompt restrictions apply to the external generator's prompt, not all diagrams. Saved image, available automated review, threshold success, and scientific correctness are distinct states. Fixed below-threshold outcomes are scenario inputs; the source's two-generation cap is recorded.

The text-only narrative cases use locally available actual sources for citation/claim comparison. Whether the reference workflow's instruction to run a network DOI helper is compulsory for a non-submission Markdown draft remains an explicit interpretation ambiguity; finite modeling does not prove it waived. This is flagged for independent review rather than erased.

The neutral scenarios describe installed Python CLIs/services but do not supply executor tool IDs or tool schemas. Therefore tool_call and live tools are not invented. Documented Python interfaces and CLI commands are mapped in raw extraction; prerequisites model declared availability only.

## Explicit adaptation assumptions

A-native: native-model extraction; no provider execution, labels or checker output consulted.
A-peer-priority: peer source priority 0, no inferred numerical hierarchy.
A-declared-capabilities: capabilities/outcomes come from frozen scenarios; none measured.
A-finite-abstraction: deterministic state transitions summarize only stated stages; no scientific validity guarantee.
A-no-invented-tool: no live tool manifest supplied; interface mapping is documentation only.
A-review-required: candidate status; independent review must authorize a separate accepted copy.
A-fresh-destination: a fresh local scaffold output path can be selected; no overwrite is assumed or authorized. This extra ordinary-filesystem assumption is visible for reviewer scrutiny.

Exclusions: complete-prose correctness; live execution/service checks; biological validity; human-gold judgments; full statistical design, object identity/aliasing, state mutation, epistemic verification, numeric image accounting, every optional source branch, and external links beyond captured dependency texts.
